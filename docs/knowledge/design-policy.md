# 設計方針

## 画面の状態

- 既定値を持つ選択項目（レーン・ランク帯・地域）は、許可値の一覧（`lib/constants.ts`）で確かめてから使う。ブラウザに保存した値や URL から来た値を、確かめずに API に渡さない
- パッチは覚えない。開くたびに最新のパッチを選ぶ（01 FR-03。古いパッチの数字を気づかずに見続けないため）
- ブラウザの保存領域が使えなくても、画面は保存なしで動くようにする

## API を呼ぶタイミング

- 画面を開いたとき、保存した条件を読み終える前に、既定値で API を呼ばない（同じ一覧を2回取りにいかないため）
- 画面から API を読むときは `useApiList` を使う。画面に `fetch` を直接書かない（失敗の扱いと、前の条件の応答を捨てる処理を1か所にするため）

## 取得できないとき

- API から取得できないときは、「読み込み中」のままにせず、取得できなかったことを画面に出す。原因（通信・エラーの応答）ごとには分けない

## データを置く場所

- データを置く場所を足したら（ブラウザの中でも）、02 の「コンポーネント詳細」に書く（2026-11-27 のユーザーの判断。置き場所の一覧から漏れないようにするため）
