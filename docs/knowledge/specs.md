# 既存の仕様（設計書に書いていない動きや前提）

## 画面

- 先出しピック・カウンターピックの2画面は、どちらもクライアントコンポーネント（`'use client'`）で、開いたときに `/api/patches` を呼び、返った一覧の先頭（最新）のパッチを選ぶ
- トップページ（`app/page.tsx`）の下の「現在の設定」は固定の文字（`JP / Patch 14.21 / Diamond+`）で、実際の既定値（Platinum+）や、覚えた絞り込み条件とは連動していない

## ブラウザに保存するもの

- 絞り込み条件（レーン・ランク帯・地域）だけ。キー・形式・既定値は 03 の 5章
- 個人を特定する情報や、認証の情報は保存していない

## API の呼び出しの見え方

- API の応答には `stale-while-revalidate` が付いている（`lib/api.ts`）。ブラウザで読み込み直すと、画面からの呼び出し1回に加えて、ブラウザがキャッシュの再検証のリクエストを足すので、DevTools の Network では同じ URL が2行になる。回数を数えるときは「Disable cache」をオンにする
- `next dev`・`next build` は、Next.js に既知の脆弱性があるバージョンのとき、アップグレードの案内を表示して1回目が止まることがある（もう一度流すと動く）。`next dev` は `AGENTS.md` を作るが、コミットしない
