1

共通仕様

項目内容
エンドポイント/api/champions・/api/counter・/api/patches の3つ。すべて GET・JSON を返す
認証アプリでの認証はなし（個人利用ツール）。ただしデプロイ全体を Vercel Authentication（All Deployments）で保護しているため、Vercel にログインしていないリクエストはアプリに届かず、Vercel のログイン画面に飛ばされる（v1.0.1 で追記。02「Webアプリ」）。API Routes はサーバー側で Supabase の anon キーを使い、RLS で SELECT のみ許可されたテーブルを参照する
入力チェッククエリパラメーターは許可値リスト（2章）で検証し、許可値以外は 400 を返す
エラー応答{ "error": "メッセージ" } の形で返す。400: パラメーター不正（どのパラメーターが不正かを書く）／500: DB エラーなど。500 では Supabase のエラー内容をそのまま返さず、"Internal Server Error" とする（内部情報を出さないため）。詳細はサーバーのログに出す
キャッシュ成功（200）の応答に Cache-Control: s-maxage=3600, stale-while-revalidate=86400 を付け、Vercel の CDN でクエリ文字列ごとにキャッシュする。エラー応答には Cache-Control: no-store を付けてキャッシュしない
キャッシュの方針（Why）: 集計データが変わるのは1日1回のバッチ実行時（JST 01:37 に起動し、起動から最大約6時間。起動が遅れた分だけ時間帯もずれる〔初回は JST 08:22 起動〕。v1.0.2 で変更。以前は JST 02:00。GitHub の混雑で遅れることがある。書き込みは500試合ごと）だけなので、1時間キャッシュしてもほぼ影響がない。表示が速くなり、Supabase 無料枠の転送量も減る。キャッシュが切れた後の最初のアクセスは古い応答をすぐ返し、裏で新しい応答を取り直す（stale-while-revalidate）。バッチ直後の最大1時間は前日のデータが表示されることを許容する。
検討して採用しなかった案: キャッシュしない（毎回 DB に問い合わせる）／バッチ完了時にキャッシュを消す（バッチから Vercel を呼ぶ仕組みと秘密鍵の管理が増え、個人利用には大げさ）。

パラメーターの許可値

値は lib/constants.ts と DB のカラム値（04 DB設計書「マスター値一覧」）に一致させる。

パラメーター許可値説明
laneTOP JG MID BOT SUPレーン
regionJP KR NA EUW EUNE地域。現在データを収集しているのは JP のみ
tierall platinum_plus diamond_plus master_plusランク帯。_plus が付く値はそのランク以上をすべて含む（例: platinum_plus = Platinum・Emerald・Diamond・Master・Grandmaster・Challenger）。all は収集したすべての試合。試合のランク帯は参加者10人の平均ランクで決まる（計算方法は 04 DB設計書）
patch14.21 の形（数字.数字）パッチ番号。/api/patches が返す値のいずれか
2.1

最低試合数の既定値（min_games）

エンドポイントallplatinum_plusdiamond_plusmaster_plus
/api/champions1001005030
/api/counter20020010050

値は lib/constants.ts の DEFAULT_MIN_GAMES。

決め方（Why）: 上のランク帯ほど試合が集まりにくい（4ランクを同じ数ずつ集めると、1日あたり platinum_plus : diamond_plus : master_plus ≒ 1 : 1/2 : 1/4）。どのランク帯でも条件を満たすチャンピオンが出るよう、データのたまり方の比率に合わせて下げる。
参考: 勝率 50% 前後での 95% のぶれ幅は、200試合 ±6.9pt／100試合 ±9.8pt／50試合 ±13.9pt／30試合 ±17.9pt。チャンピオン間の勝率差は数ポイントのことが多く、少ない試合数の値はぶれが大きい。画面には試合数を必ず表示し、利用者が判断できるようにする。
3

GET/api/champions

先出しピック画面（SCR-02）用。指定したレーンのチャンピオンを勝率の高い順に返す。対応する要件: FR-01〜FR-07。カウンターピック画面（SCR-03）でも、相手チャンピオンの選択肢を出すために使う。

クエリパラメーター

名前必須既定値説明
lane必須—2章の許可値
patch必須—2章の形式
region任意JP2章の許可値
tier任意platinum_plus2章の許可値
limit任意20返す件数。上限 100（超えた場合は 100 にする）。正の整数でなければ 400
min_games任意tier による（下表）この試合数未満のチャンピオンは返さない（統計の信頼性のため）。0 以上の整数でなければ 400。指定した場合は tier に関係なくその値を使う

処理

champion_stats を lane・patch・region・tier で絞り込み、games_played >= min_games のものを win_rate の高い順に limit 件返す。チャンピオン情報は champions を JOIN して付ける。

応答（200）

[
  {
    "win_rate": 0.574,          // 0〜1 の小数
    "games_played": 9821,
    "champions": {
      "champion_id": 58,
      "champion_name": "レネクトン",
      "champion_key": "Renekton",
      "image_url": "https://ddragon.leagueoflegends.com/cdn/14.21.1/img/champion/Renekton.png"
    }
  }
]

該当データがない場合は空配列 [] を返す（エラーにしない）。

4

GET/api/counter

カウンターピック画面（SCR-03）用。指定した相手チャンピオンに対して、同じレーンで勝率の高いチャンピオンを返す。対応する要件: FR-10〜FR-14。

クエリパラメーター

名前必須既定値説明
enemy_champion_id必須—相手チャンピオンの ID（正の整数）
lane必須—2章の許可値
patch必須—2章の形式
region任意JP2章の許可値
tier任意platinum_plus2章の許可値
limit任意15返す件数。上限 100。正の整数でなければ 400
min_games任意tier による（下表）この対戦数未満の組み合わせは返さない。0 以上の整数でなければ 400。指定した場合は tier に関係なくその値を使う

処理

counter_stats を enemy_champion_id・lane・patch・region・tier で絞り込み、games_played >= min_games のものを win_rate の高い順に返す。counter_stats には champions への外部キーが2本（自分側・相手側）あるため、JOIN では自分側の外部キーを明示する（champions!counter_stats_champion_id_fkey(...)）。

応答（200）

/api/champions と同じ形。win_rate は「相手チャンピオンと対面したときの勝率」、games_played はその対戦数。

5

GET/api/patches

パッチ選択のプルダウン用。集計データが存在するパッチを新しい順に返す。パラメーターなし。

応答（200）

["14.21", "14.20", "14.19"]
実装上の注意
・並び順は数値として比べる（文字列で比べると 14.9 が 14.10 より新しくなってしまう）
・Supabase（PostgREST）の select は1回最大1000行しか返さないため、champion_stats の全行を取ってから重複を除く方法は使わない。重複除去は DB 側で行う

実装状況（2026-11-02 時点）

3つの API はモックデータ（lib/mock-data.ts）を返す仮実装で、Supabase にはまだ接続していない。接続時にこの設計書の仕様に合わせる。

Supabase からの取得（patch・region・tier での絞り込み、500 エラー応答を含む）未実装モックデータを返している
