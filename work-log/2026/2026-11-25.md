- `~/Claude` のルールの一覧を作り、このプロジェクトと比べた。コードの書き方の規約は、書式・`interface` と `type`・`enum` や `any` を使わない点などで、今のコードと同じだった

### 決めたこと（とその理由）

- `~/Claude` のルールは全部消す（ユーザーの判断）。このプロジェクトのルールはプロジェクトの中にあるので、移動してもそのまま効く。`~/Claude/CLAUDE.md` に写すと、`~/Claude` の下のほかのプロジェクトにもこのプロジェクトのルールが当たるため、写さない
- コードの書き方は A案にした（ユーザーの判断）。要点だけを `coding.md` に移す。`app/`・`components/`・`lib/`・`scripts/` を扱うときだけ読み込まれるので、毎回読む量は増えない
- 今のコードと照らして、合わないものは移さなかった
  - 1行100文字まで: 100文字を超える行が多い（コメント以外の行にもある）
  - `import type` を最後のグループにまとめる: `type` を付けて同じ import に含めている箇所が多い
  - 複数行の末尾のカンマ: 確かめていないため
  - PR のスクリーンショット・本文の型・テストの書き方: 進め方は `pr-review` スキルと `test-spec.md` にあるため
- 今のコードで外れている次の箇所は、そのファイルを直すときに合わせる。どれも動きには関わらないので、今回は直さない
  - `.then()`: `app/counter-pick/page.tsx`・`app/first-pick/page.tsx`
  - モックを返す API Routes に `try/catch` がない
  - `!`: `scripts/collector.ts`（97・123・141行）
  - 理由のコメントがない `as`: `app/api/*/route.ts`・両方のページ・`scripts/collect.ts`・`scripts/riotClient.ts`
  - 戻り値の型がない export 関数: `scripts/supabaseWriter.ts` の4つ
  - 名前: 型 `Tier_Label`、真偽値の `loading`・`loadingList`・`loadingCtr`
  - 理由のコメントがない `useEffect(..., [])`: 両方のページ
- レビュー（PR #39）の指摘で直した
  - 文字とバッジの色の規約は、白い背景が前提で、03 の濃い背景の配色と食い違う。「配色は 03 に従う」に変えた
  - 戻り値の型は、React のコンポーネントと route handler を対象から外した。今のコードは8つとも書いておらず、型の推論で足りるため
  - `as` にコメントを書く規約から `as const` を外した。テストのファイルでは、モックのための `as`・`!` を使ってよいとした
  - API のエラーの応答は、05 の1章と `lib/api.ts` を参照する形にした（同じことを2か所に書かないため）
